# Network Monitor Node — Saved Metrics Reference

This document explains **all persisted metrics/data products** generated by `src/network_monitor/src/network_monitor_node.cpp`.

Output files are written under:

- `<output_dir>/<run_id>/...` (defaults to `log/run0/...`)

The node saves data in two modes:

- **Periodic flush** via `csv_timer_` (`csv_write_period_sec`, default 10s): calls `writeOutputs(false)`
- **Shutdown/final flush** via `on_shutdown` and destructor: calls `writeOutputs(true)` and rewrites complete snapshots for append-style files.

It also writes time-series rows continuously through dedicated timers.

---

## 1) `messages.csv`

### Source and extraction
Built from in-memory `records_` (`MsgRecord`), populated by:

- `/fanet/network_bus_raw` → `trafficRawCallback(...)` (initial observation/generation accounting)
- `/fanet/network_bus` → `trafficCallback(...)` (forwarding count, DROP/ACK correlation metadata)
- `/fanet/delivered` → `deliveredCallback(...)` (delivery time, hops, ttl)

DROP and ACK are reconciled through:

- `drop_by_ref_` (from `control_type == "DROP"`)
- `ack_by_ref_` (from `control_type == "ACK"`)
- merged in `reconcileCausality()` before writing.

### When saved
- On every periodic `writeOutputs(false)`
- On final flush `writeOutputs(true)`

### What it represents
Per-message lifecycle and reliability trace.

Columns:
- `run_id`
- `msg_id`, `flow_type`, `control_type`, `src_id`, `dst_id`
- `creation_time_s`
- `delivered_time_s`, `delivered`
- `e2e_delay_ms` (`delivered_time - creation_time`, else `-1`)
- `forward_count`, `hop_count`, `ttl_hops`
- `payload_bytes`
- `dropped`, `drop_reason`, `dropper_id`
- `ack_time`

---

## 2) `qos_metrics.csv`

### Source and extraction
Computed from `records_` by:

- `buildQosStats()` → aggregates by key `flow_type:control_type`
- `finalizeQosStats(...)` → derives QoS metrics using configured targets/weights.

### When saved
- On every periodic/final `writeOutputs(...)`

### What it represents
QoS summary per message category (`flow_type`, `control_type`).

Columns:
- `generated`, `delivered`, `dropped`
- `pdr = delivered / generated`
- `delay_mean_ms`, `delay_p95_ms`
- `jitter_ms` (mean absolute successive delay difference in time order)
- `throughput_bps` (delivered payload bits over active duration)
- `generated_bps`
- `qos_score` (weighted normalized score using `qos_target_*` and `qos_weight_*` parameters)

---

## 3) `charge_events.csv`

### Source and extraction
Built from `charge_records_` (`ChargeRecord`), fed by multiple streams:

- `CHARGE_REQUEST` traffic on `/fanet/network_bus` (`trafficCallback`) creates/updates request record.
- Delivered `CHARGE_DECISION` on `/fanet/delivered` (`deliveredCallback`) sets decision timing/outcome and parses rationale (`policy`, `priority`, `rank_index`, `queue_size`, `tte_sec`, `score`).
- `/fanet/status` (`statusCallback`) detects docking start, charge completion, and preemption-like return-before-dock transitions.
- DROP traffic can mark request as routing dropped.
- `checkChargeTimeouts()` marks undecided requests as timeout.
- Failure events can mark energy depletion (`ENERGY_DEPLETED`).
- Decision-context QoS for `CHARGE_DECISION` is injected from current `buildQosStats()` snapshot.

### When saved
- On every periodic/final `writeOutputs(...)`

### What it represents
Per charging request end-to-end decision and execution outcome.

Key columns include:
- identity: `request_msg_id`, `uav_id`, `ugv_id`, `role`
- outcome: `outcome`, `failure_reason`, `charge_completed`, `preempted_flag`, `preempt_count`
- timings: `request_time`, `decision_time`, `dock_start_time`, `charge_end_time`, `terminal_time`
- derived latencies: `decision_latency_ms`, `waiting_time_ms`, `charge_duration_ms`, `effective_wait_ms`
- energy: `request_battery`, `start_battery`, `end_battery`, `energy_recovered`
- decision metadata: `decision_policy`, `decision_priority`, `decision_tte_sec`, `decision_score`, `decision_rank_index`, `decision_queue_size`
- network-at-decision context: `decision_ctrl_pdr`, `decision_ctrl_delay_mean_ms`, `decision_ctrl_delay_p95_ms`, `decision_ctrl_drop_reasons`

## 4) `recovery_events.csv`

### Source and extraction
Generated by `trackRecoveryEvent(...)` from `/fanet/network_bus` messages with `flow_type == 1` and control types:

- `RECOVERY_START`, `RECOVERY_DONE`
- `CLUSTER_REASSIGN`
- `TASK_ASSIGN`
- `NEW_DEPLOYMENT`
- `EMERGENCY_RETURN_TRIGGERED`
- `RESPAWN_COMPLETED`

Payload parsing rules:
- recovery start/done: `epoch` from payload integer
- cluster reassign: `member_id = dst_id`, `ch_id = payload`
- task assign: `task_count` from `;`-separated payload tokens
- new deployment: parses `x,y,z` pose from payload
- respawn completed: `member_id = src_id` and UAV removed from dead set if present.

### When saved
- On every periodic/final `writeOutputs(...)`

### What it represents
Discrete recovery/control-plane events used for resilience and reconfiguration analysis.

Columns:
- `msg_id`, `control_type`, `src_id`, `dst_id`
- `epoch`, `member_id`, `ch_id`, `task_count`
- `x`, `y`, `z`
- `creation_time`

---

## 5) `death_events.csv`

### Source and extraction
Created in `handleFailureFromTraffic(...)` when a `FAILURE_EVENT` payload decodes to `failure_type == 1` (battery dead).

Event uses:
- time from message creation stamp
- role/battery from latest known UAV status/role maps.

### When saved
- On every periodic/final `writeOutputs(...)` (only if at least one event exists)

### What it represents
Per-UAV death records for survival analysis (Kaplan–Meier style curves).

Columns:
- `time`, `uav_id`, `role`, `cause`, `battery_at_death`
- `fleet_size`, `alive_count` (alive estimate after each death event index)

---

## 6) `status_timeseries.csv`

### Source and extraction
Snapshot rows built from `uav_states_`, which is updated by `/fanet/status` in `statusCallback(...)`.

### When saved
- Periodically by `status_timeseries_timer_` every `status_sample_period_sec` (default 1s)
- Also once during each `writeOutputs(...)` call.

### What it represents
Per-UAV state timeline for mission/charging behavior.

Columns:
- `time`, `uav_id`, `role`, `charging_state`
- `battery_level`, `backbone_active`
- `x`, `y`, `z`
- `energy_consumption_rate`

---

## 7) `weather_timeseries.csv`

### Source and extraction
Current weather cache updated by `/environment/weather` in `weatherCallback(...)`.
Rows are written only after at least one weather message (`weather_received_ == true`).

### When saved
- Periodically by `weather_timeseries_timer_` every `status_sample_period_sec`
- Also once during each `writeOutputs(...)`.

### What it represents
Environment/weather timeline for correlation with network and fleet behavior.

Columns:
- `time`, `regime`
- `temperature_c`, `wind_speed`, `wind_direction_deg`, `rain_intensity`

---

## 8) `charge_queue_timeseries.csv`

### Source and extraction
Hybrid queue snapshot from:

1. `charge_records_` + outcomes (pending/not-started request counting and wait means)
2. `uav_states_` (`charging_state` distribution and mission/charging counts)
3. `latest_ugv_charging_snapshot_` from `/ugv/charging_snapshot` JSON-like string (`active_sessions_count`, `queue_length`, `max_parallel_spots`) which overrides computed UGV-side counts when present.
4. Dead UAV sets/history from failure handling.

### When saved
- Periodically by `queue_timeseries_timer_` every `queue_stats_period_sec` (default 1s)
- Also once during each `writeOutputs(...)`.

### What it represents
Queue congestion, charging occupancy, and consistency checks between UAV-status inference and UGV-reported charging snapshot.

Columns:
- queue composition: `queue_length_ugv`, `queue_length_ch`, `queue_length_member`, `queue_length_unknown`
- capacity/occupancy: `active_charging_ugv_sessions`, `ugv_dock_capacity`, `ugv_dock_utilization`
- waits: `mean_wait_ch_ms`, `mean_wait_member_ms`
- fleet activity: `active_mission_count`, `active_charging_uav_status`, `going_to_ugv_count_uav_status`, `returning_count_uav_status`
- survival counters: `current_dead_count`, `dead_event_count`, `fleet_size`
- consistency indicators: `over_capacity_ugv`, `status_vs_ugv_gap`

## 9) `network_timeseries.csv`

### Source and extraction
Sliding-window computation over `records_` in `writeNetworkTimeseriesRow()`.
The window is `rate_window_sec_` (`network_stats_window_sec`, default 10s), using `creation_time` cutoff.

It computes:
- all-message window totals (`generated/delivered/dropped`)
- window PDR/delay/jitter
- specific control-type reliability for `CHARGE_REQUEST` and `CHARGE_DECISION`.

### When saved
- Periodically by `network_timeseries_timer_` every `status_sample_period_sec`
- Also once during each `writeOutputs(...)`.

### What it represents
Short-horizon network robustness and charging-control-channel reliability.

Columns:
- `window_generated`, `window_delivered`, `window_dropped`, `window_pdr`
- `window_delay_mean_ms`, `window_delay_p95_ms`, `window_jitter_ms`
- `ctrl_charge_req_generated`, `ctrl_charge_req_delivered`, `ctrl_charge_req_pdr`
- `ctrl_charge_dec_generated`, `ctrl_charge_dec_delivered`, `ctrl_charge_dec_pdr`

---

## 10) `summary.json`

### Source and extraction
Generated in `writeSummaryJson()` from current in-memory aggregates:

- fleet/death state (`uav_states_`, `dead_uavs_`, death history)
- charging outcomes and derived stats from `charge_records_`
- per-UAV fairness indicators (rejections/timeouts/max wait)
- network QoS categories from `buildQosStats()` + `finalizeQosStats()`
- recovery event counters from `recovery_counts_`.

### When saved
- Every `writeOutputs(...)` call (periodic and shutdown), overwritten (`trunc`) each time.

### What it represents
Run-level snapshot with grouped KPIs:
- `fleet`: size, alive/dead, survival rate
- `charging`: totals by outcome, success rate, latency/wait/energy summaries
- `charging_fairness`: per-UAV rejection/timeout/max-wait maps
- `network`: configured QoS targets/weights plus per-category metrics and drop reasons
- `recovery`: counts of major recovery control events

---

## 11) `preemption_events.csv` (conditionally present)

> This file is written only if at least one preemption event is captured.

### Source and extraction
Preemption events are collected from:
- `/ugv/queue_events` strings containing `event=PREEMPTION` (`queueEventCallback(...)` key=value parsing)
- delivered `CHARGE_DECISION` payloads containing `reason=PREEMPTED` (marks request preempted and records event linkage).

### When saved
- On periodic/final `writeOutputs(...)` **if** `preemption_events_` is non-empty.

### What it represents
Detailed preemption transitions for policy/fairness analysis.

Columns:
- `time`, `victim_uav_id`, `winner_uav_id`
- `victim_role`, `winner_role`
- `victim_priority`, `winner_priority`, `delta_priority`
- `victim_charge_time_s`, `policy`

## Topic-to-file traceability (quick map)

- `/fanet/network_bus_raw` → `messages.csv`, `qos_metrics.csv`, `network_timeseries.csv`, `summary.json`
- `/fanet/network_bus` → `messages.csv`, `qos_metrics.csv`, `charge_events.csv`, `recovery_events.csv`, `death_events.csv`, `network_timeseries.csv`, `summary.json`
- `/fanet/delivered` → `messages.csv`, `qos_metrics.csv`, `charge_events.csv`, `network_timeseries.csv`, `summary.json`, `preemption_events.csv`
- `/uav_fleet/charge_requests` + `/ugv/charge_decisions` + `/fanet/status` → `charge_events.csv`, `charge_queue_timeseries.csv`, `summary.json`
- `/fanet/status` → `status_timeseries.csv`, `charge_queue_timeseries.csv`, `death_events.csv`, `summary.json`
- `/environment/weather` → `weather_timeseries.csv`
- `/ugv/charging_snapshot` → `charge_queue_timeseries.csv`
- `/ugv/queue_events` → `preemption_events.csv`
